## 0807: 실데이터 DAG 실행과 멱등성 확인 회고

### 진행 내용
- **실데이터 수집:** 서울 공공자전거 API에서 이틀간의 데이터를 페이지 단위로 수집하였다.
- **DAG 전체 실행:** 초기화, 수집, 정제·집계, MySQL 적재, 품질 검사 태스크를 순서대로 실행하였다.
- **결과 검증:** Airflow UI와 태스크 로그, MySQL 결과를 확인하고 수집·집계 로직을 보완하였다.

---

### 오늘 배운 내용
오늘은 전날 정리한 Airflow ETL을 실제 데이터로 다시 실행하였다. 원본 데이터를 파일에 저장하고 XCom에는 파일 경로와 행 수처럼 작은 메타데이터만 전달함으로써 태스크 사이에서 큰 데이터를 직접 주고받지 않도록 구성하였다.

같은 기간의 DAG를 다시 실행해도 기존 결과가 중복되지 않는지 확인하면서 멱등성의 의미를 더 구체적으로 이해할 수 있었다. 또한 마지막 품질 검사 태스크가 행 수, 중복, 결측값과 집계 총합을 확인하도록 하여 적재 성공과 데이터 정상 여부는 별도로 검증해야 한다는 점을 배웠다.

---

### KPT 회고

#### **Keep - 유지할 점**
코드만 보고 완료했다고 판단하지 않고 실제 API, Airflow, MySQL을 연결해 끝까지 실행한 점은 유지하고 싶다. 태스크 로그와 최종 SQL 결과를 함께 확인한 과정도 도움이 되었다.

#### **Problem - 문제점**
실제 데이터를 사용하자 수집 시간과 페이지 처리, 집계 결과처럼 작은 예제에서는 드러나지 않던 문제를 만났다. 실행이 성공해도 데이터가 정확한지는 별도 검사가 없으면 확신하기 어려웠다.

#### **Try - 시도할 점**
앞으로는 개발 초기에 작은 데이터로 빠르게 확인한 뒤 반드시 실제 규모의 데이터로 통합 실행하겠다. 최종 태스크에는 데이터 품질 조건과 기대 결과를 명시하여 성공 여부를 자동으로 판단하도록 하겠다.

---

### 이번 주 개선 목표
- **실데이터로 검증하기:** 샘플뿐 아니라 실제 데이터와 실행 환경에서 전체 흐름을 확인한다.
- **XCom 사용 범위 지키기:** 원본 데이터 대신 경로와 처리 건수 등 메타데이터만 전달한다.
- **품질 검사 자동화하기:** 행 수, 유일성, 결측값과 집계 결과를 DAG에서 검사한다.
- **실행 결과 기록하기:** Airflow 성공 화면과 SQL 결과를 문서에 남긴다.
