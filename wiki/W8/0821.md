## 0821: 변경 감지와 버전 보존으로 파이프라인 효율화 회고

### 진행 내용
- **변경 없는 처리 생략:** 월별 운행, 기사 스냅샷과 보유 차량의 Bronze가 이전과 같으면 후속 처리를 건너뛰도록 하였다.
- **Silver 버전 보존:** 수집 시각별로 Silver 결과를 구분해 같은 대상 월의 변경 이력을 남겼다.
- **원천 감시 구성:** Source API 완료 신호를 통일하고 변경된 원천만 감지해 Gold를 한 번 실행하도록 하였다.
- **운영 가시성 개선:** HVFHV 품질 경고와 Slack Block Kit 알림을 추가하고 Source API 배포 검증을 보강하였다.

---

### 오늘 배운 내용
오늘은 데이터가 실제로 바뀌지 않았는데도 모든 계층을 다시 처리하는 비용을 줄였다. 대상 월이 같다는 사실만으로 동일한 데이터라고 판단할 수는 없기 때문에 원천의 내용과 수집 상태를 비교하고, 변경이 없을 때만 Bronze 이후 단계를 생략하였다.

반대로 같은 월의 데이터가 다시 수집되어 내용이 바뀔 수 있으므로 Silver는 수집 시각별 버전을 보존하였다. 이를 통해 최신 결과를 제공하면서도 과거 실행을 추적할 수 있었다. 여러 원천의 완료 신호는 하나의 계약으로 통일하고, 알림에는 실패 원인과 대응에 필요한 정보만 읽기 쉽게 담는 것이 운영 효율에 중요했다.

---

### KPT 회고

#### **Keep - 유지할 점**
데이터 변경 여부를 확인해 불필요한 처리를 줄이면서도 과거 버전을 보존한 점은 유지하고 싶다. 품질 경고와 배포 검증을 함께 보강해 운영 흐름 전체를 본 것도 좋았다.

#### **Problem - 문제점**
`latest`가 단순히 가장 최근 월을 가리키면 실제 데이터셋이 없는 월을 선택할 수 있었다. 여러 완료 신호가 섞여 Gold가 중복 실행될 가능성도 있었고, 배포 환경의 API 주소 오류는 실행 전까지 발견하기 어려웠다.

#### **Try - 시도할 점**
최신 버전은 실제 데이터가 존재하는 범위에서만 선택하겠다. 변경 감지와 이벤트 병합 규칙을 문서화하고, 배포 전에 주소 형식과 연결 가능성을 검사하겠다.

### 이번 주 개선 목표
- **불필요한 재처리 줄이기:** 입력 내용이 동일하면 안전하게 후속 단계를 생략한다.
- **수집 버전 보존하기:** 대상 월과 수집 시각을 분리해 변경 이력을 추적한다.
- **완료 신호 단일화하기:** 여러 원천의 이벤트가 Gold 중복 실행으로 이어지지 않게 한다.
- **알림 가독성 높이기:** 장애 원인, 대상 데이터와 대응 정보를 한눈에 확인할 수 있게 한다.
