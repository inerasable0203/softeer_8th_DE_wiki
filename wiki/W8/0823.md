## 0823: 서비스 지역 확장과 Gold 실행 비용 최적화 회고

### 진행 내용
- **지역별 경로 적용:** 월별 운행, 기사 차량과 보유 차량의 Bronze·Silver 경로에 `service_area`를 반영하였다.
- **버전 경로 정리:** Bronze는 `collected_at`, Silver는 `source_collected_at`을 기준으로 원천 API 경로를 구분하였다.
- **Gold 모델 확장:** 기사별 차량 수익 시뮬레이션을 적재하고 최종 추천 검증과 분리하였다.
- **Spark 최적화:** Silver→Gold 과정의 불필요한 Shuffle과 Stage 실행 비용을 줄였다.

---

### 오늘 배운 내용
오늘은 뉴욕 한 지역을 전제로 하던 경로를 여러 서비스 지역을 지원할 수 있도록 변경하였다. 파일 안에 지역 컬럼만 추가하는 것으로는 충분하지 않았고, S3 경로 탐색과 API 조회, Spark 입력 선택까지 동일한 지역 계약을 사용해야 서로 다른 지역의 데이터가 섞이지 않았다.

Gold에서는 최종 추천만 저장하던 구조를 기사와 후보 차량별 수익 시뮬레이션과 실제 추천 결과로 분리하였다. 중간 계산을 별도 데이터로 남기니 추천 근거를 설명하고 검증하기 쉬워졌다. 동시에 실행 계획을 확인해 반복 조인과 불필요한 Shuffle을 줄이면서 결과의 의미를 유지한 채 비용을 낮추는 방법을 고민하였다.

---

### KPT 회고

#### **Keep - 유지할 점**
지역 확장을 단일 컬럼 변경이 아니라 API, 저장 경로와 Spark 탐색 전체의 계약으로 본 점은 유지하고 싶다. 시뮬레이션과 최종 추천을 분리해 설명 가능성을 높인 것도 좋았다.

#### **Problem - 문제점**
서비스 지역 경로 모듈이 패키징에서 빠지거나 일부 데이터셋만 이전 계약을 사용해 실행 오류가 발생했다. 경로 계약 변경이 여러 계층에 동시에 퍼져 수정 누락 위험이 컸다.

#### **Try - 시도할 점**
지역과 버전 경로는 공통 모듈에서 생성하고 모든 데이터셋에 대한 계약 테스트를 만들겠다. Spark 최적화 전후에는 실행 계획과 결과 건수를 함께 비교하겠다.

---

### 이번 주 개선 목표
- **지역 격리 보장하기:** 서로 다른 서비스 지역의 데이터가 경로와 조인에서 섞이지 않도록 한다.
- **버전 경로 통일하기:** 수집 시각과 원천 수집 시각의 의미를 계층별로 일관되게 사용한다.
- **추천 근거 보존하기:** 시뮬레이션 결과와 최종 배정 결과를 구분해 추적한다.
- **Spark 비용 측정하기:** Shuffle, Stage와 실행 시간을 변경 전후로 비교한다.
